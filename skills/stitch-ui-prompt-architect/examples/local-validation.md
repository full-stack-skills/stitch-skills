# Stitch 提示词设计：本地应用验证

以下是完整的中文请求与预期响应契约，使用演示资料；不是远程执行记录。不调用 Stitch 写操作即可检索、模拟应用并审阅结果。

## 快速开始

输入：“润色门店预约页的模糊 Stitch 提示。只用演示素材，先返回本地结果与验证范围。”

输出：[Context] 门店预约平板页，只编辑顶栏。
[Layout] 1. 在头像前放搜索输入。
[Components] 标签“搜索订单”，占位“输入订单号”，清除动作与焦点态。

验证：三段顺序和设备明确；若示例无远程环境，明确远程状态未执行。

## 典型场景

输入：“把 TABLET Spec 和 uView Pro 契约组装为提示；范围限当前需求。”

输出：按顺序列出明确 platform、purpose 和真实文案；缺项给标注假设的可用提示。 根据可观察的系统状态分流：已应用系统的新屏去掉主题tokens；prompt-only/legacy内联；targeted-edit只写请求的差值。 输出 [Context]、[Layout]、[Components] 三段，布局编号，控件有具体标签和状态。 最后返回已处理对象与来源，未运行的项目单列。

验证：已应用系统提示不重复hex/font/theme/radius。

## 高级场景

输入：“为既有屏幕只增加搜索栏编写精确编辑描述；定制参数为设备、路径A/B、框架、文案、系统状态和目标区域。”

输出：保留所选参数、模糊词转组件；双路径三段契约；系统/内联/编辑分流，提供编辑只覆盖请求区域的判据；假设不冒充实际配置。

## 异常处理

输入：“润色门店预约页的模糊 Stitch 提示，但暂时缺少页面目的、内容与目标设备。”

输出：“先给本地假设草案。需要补充：页面目的、内容与目标设备，用于确定真实来源；未执行依赖该来源的写操作。”不返回空答复，也不伪造成功。

## 避免误触发与验证

输入：“实际生成/编辑屏幕，不扩大任务。”

输出：“使用stitch-ui-designer；交接当前素材和请求，当前入口不执行额外动作。”

检查：以上五种请求分别检索快速、典型、高级、失败、边界路径；检查输出中的 ID、token、运行结论是否均有输入/回执依据。此人工应用检查不等价于独立模型触发率统计。
